# Module I18n

Modules can ship translations through two parallel contracts:

- nested area messages for `useAreaMessages()` / `getAreaMessages()`
- flat natural-key translations for `createTranslator()` / `useI18n()`

The host keeps both systems in parallel. Flat keys do not replace the typed
module message tree.

## 1. Nested area messages

Use nested JSON files when the module needs typed area-scoped messages under
`messages.mod['mod.<moduleId>']`.

Source layout:

```text
modules/<moduleId>/i18n/<area>/<locale>.json
```

Compiled/prebuilt layout:

```text
modules/<moduleId>/dist/i18n/<area>/<locale>.json
```

Supported areas:

- `global`
- `dashboard`
- `admin`
- `login`

Example:

```json
{
  "title": "Analytics",
  "nav": {
    "overview": "Overview"
  }
}
```

The generator stores those trees under:

```text
messages.mod["mod.analytics"]
```

Build command:

```bash
pnpm modules:i18n
```

Generated output:

```text
lib/i18n/messages/modules.generated.ts
```

## 2. Flat natural-key translations

Use flat JSON files when the module needs ad-hoc translation lookups by English
source string.

Source layout:

```text
modules/<moduleId>/i18n/translations/<locale>.json
```

Compiled/prebuilt layout:

```text
modules/<moduleId>/dist/i18n/translations/<locale>.json
```

Example:

```json
{
  "Create item": "Crear elemento",
  "Settings saved": "Configuracion guardada"
}
```

Rules:

- keys must be English source strings
- values must be translated strings
- the file must be a flat JSON object; nested objects are invalid
- if `dist/i18n/translations` exists, the host reads `dist` and ignores source
  files for that module
- the same `locale + key` pair may appear in multiple sources only if the
  translated value is identical
- if two sources define the same `locale + key` with different values,
  `pnpm i18n:prepare` fails

Build command:

```bash
pnpm i18n:prepare
```

Generated output:

```text
lib/i18n/translations.generated.ts
```

## 3. Locale behavior

Locales are inferred from JSON filenames, so modules can ship any locale
without editing host TypeScript imports.

Core typed messages still define the host `AppLocale` union. If a module ships a
locale that the host has not enabled yet, the flat file is still ingested, but
the host will only use it once that locale exists in `lib/i18n/locales/*`.

## 4. Build order

Use this order when module i18n changes:

1. `pnpm modules:build`
2. `pnpm modules:prepare`
3. `pnpm modules:i18n`
4. `pnpm i18n:prepare`

`modules:i18n` builds the nested module tree. `i18n:prepare` then regenerates
the flat registry, including module flat translation files.

## 5. Example usage

Typed module messages:

```tsx
import { useAreaMessages } from '@/lib/i18n/client';

export function AnalyticsHeader() {
  const messages = useAreaMessages('admin');
  const mod = messages.mod['mod.analytics'];
  return <h1>{mod.title}</h1>;
}
```

Flat translator:

```tsx
import { useI18n } from '@/lib/i18n/client';

export function SaveNotice() {
  const t = useI18n();
  return <p>{t('Settings saved')}</p>;
}
```
